## 0. 레퍼런스에서 가져올 것 / 가져오지 않을 것

riddle은 **reMarkable Paper Pro 전자잉크 태블릿 전용 Rust 앱**입니다. 펜으로 쓰면 2.8초 뒤 페이지를 이미지로 찍어 비전 LLM에 보내고, 답장을 손글씨 폰트(Dancing Script)를 골격화(Zhang-Suen thinning)해 **한 획씩 써지듯** 재생한 뒤 잉크가 바래듯 사라집니다.

| 가져올 것 (컨셉·연출) | 가져오지 않을 것 (코드) |
|---|---|
| 낡은 일기장 종이 위에 잉크가 스며드는 질감 | Rust/전자잉크 프레임버퍼 코드 (웹 게임과 무관) |
| 글씨가 **한 획씩** 써지는 애니메이션 → 기보·해설에 사용 | reMarkable 전용 펜 입력(evdev) |
| 다 쓴 뒤 잉크가 바래며 사라지는 연출 → 턴 전환, 컷신 종료 | LLM 손글씨 인식 (체스에는 불필요, 확장 옵션으로만) |
| "일기장이 말을 건다"는 페르소나 → 해설자 캐릭터 | |

즉 **코드를 포크하는 게 아니라, 감성과 연출 문법을 웹 체스 게임으로 옮기는 프로젝트**입니다. riddle은 MIT 라이선스라 아이디어 참고는 자유롭고, Dancing Script 폰트는 OFL이라 그대로 써도 됩니다.

## 1. 한 줄 컨셉

> **"마법 일기장 위에 수채화 잉크로 그려진 체스 말들이 살아 움직이고, 말을 잡으면 일기장 한 페이지가 펼쳐지며 짧은 결투 장면이 그려진다."**

- 플랫폼: 웹 브라우저 (PC 우선, 태블릿/모바일 대응)

- 톤: 수채화·잉크 번짐, 세피아/양피지, 은은한 마법 빛. 픽셀아트 X, 실사 3D X.

## 2. 아트 방향

### 2.1 키워드
`watercolor` · `ink wash` · `wet-on-wet bleeding` · `aged parchment diary` · `hand-drawn storybook` · `loose brush strokes` · `sepia + one accent color`

### 2.2 팔레트
| 용도 | 색 | HEX (가이드) |
|---|---|---|
| 종이 바탕 | 낡은 양피지 | `#EFE3C8` |
| 종이 얼룩/그림자 | 커피 얼룩 | `#C9B08A` |
| 기본 잉크 | 철 갈색 잉크 (iron gall) | `#3B2A1E` |
| 백(White) 진영 | 청람색 잉크 | `#2F4E7A` |
| 흑(Black) 진영 | 진홍 잉크 | `#7A1F2B` |
| 이동 가능 표시 | 금빛 마법 잉크 | `#C9962E` |
| 불가 표시 | 번지는 회색 먹 | `#6B6258` |

> 두 진영은 "흰색/검정"이 아니라 **청색 잉크 vs 붉은 잉크**로 구분 → 수채화 톤과 잘 맞고 가독성이 좋음.

### 2.3 화면 질감 규칙
1. 모든 화면 뒤에 **종이 텍스처** 1장 + 가장자리 비네팅.
2. 말과 이펙트는 **가장자리가 살짝 번진** 스타일 (SVG/WebGL 변위 필터로 실시간 흔들림 2~3px).
3. 선은 균일한 벡터선 금지 → 붓 자국 텍스처/불규칙 두께.
4. 등장은 "잉크가 번져 나타남", 퇴장은 "잉크가 바래며 사라짐"으로 통일 (riddle의 fade 연출).

| 말 | 성격 | 무기/능력 (깃펜이 그림) | 공격 타입 | 성격 연출 |

| 나이트 (Knight) | 기마 기사 | 랜스 + 말 | **돌진 (Charge)** | 말이 앞발을 들고 L자로 도약 |

| 룩 (Rook) | 돌 성탑 골렘 | 거대한 주먹 | **분쇄 (Crush)** | 쿵쿵 무겁게 미끄러짐 |
| 퀸 (Queen) | 쌍검 여왕 | 쌍검 | **연속 베기 (Slash Combo)** | 회전하며 우아하게 이동 |
| 킹 (King) | 노왕 | 대검 | **일도양단 (Cleave)** | 느리고 위엄 있게 한 칸 |

## 4. 핵심 인터랙션

### 4.1 선택 & 이동 가능 칸 표시
1. 내 말 클릭 → 말이 살짝 **들어 올려짐** (y −8px, 그림자 확대, 150ms).
2. 이동 가능 칸에 **금빛 잉크 방울**이 번지며 나타남 (칸마다 30ms 시차).
3. 잡을 수 있는 칸은 방울 대신 **붉은 잉크 원 테두리**.
4. 다른 내 말 클릭 → 선택 전환. 빈 곳/같은 말 다시 클릭 → 선택 해제 (말이 내려앉음).
5. 드래그 앤 드롭도 지원 (클릭-클릭과 동일 로직).

### 4.2 합법 이동
- 말이 목적 칸으로 **곡선 궤적**으로 이동 (말 종류별 이징, 아래 표).
- 도착 시 종이에 **잉크 착지 얼룩**이 퍼졌다 사라짐.
- 이동한 경로에 옅은 **잉크 자국(trail)**이 남았다가 1초 후 바램.

| 말 | 이동 모션 | 시간 |
|---|---|---|
| 폰 | 짧게 통통 튀며 직진 | 280ms |
| 나이트 | 포물선 점프 (L자 꺾임을 공중에서) | 450ms |
| 비숍 | 미끄러지듯 활주 + 잔상 | 350ms |
| 룩 | 무겁게 직선, 도착 시 화면 미세 흔들림 | 400ms |
| 퀸 | 회전하며 활주 | 380ms |
| 킹 | 천천히 한 걸음 | 400ms |

### 4.3 불가능한 이동 → "갔다가 되돌아오기" ★핵심
갈 수 없는 칸을 클릭/드롭하면:
1. 말이 목표 쪽으로 **약 40~60% 지점까지** 이동 (200ms, ease-out).
2. 보이지 않는 벽에 부딪히듯 **찌그러짐(squash) + 회색 먹 번짐** 이펙트 + "툭" 효과음.
3. 원래 칸으로 **탄성 있게 되돌아옴** (350ms, elastic/back ease).
4. 말이 고개를 가로젓는 듯 **좌우 흔들림** 2회.
5. (옵션) 일기장 여백에 해설이 한 획씩 써짐: *"그 길은 막혀 있다."*
6. 이유가 있으면 해설을 구체화: 체크 상태라 불가 → *"왕이 위험하다…"*, 핀 상태 → *"그 병사는 움직일 수 없다. 왕을 지키고 있다."*

> 드래그로 놓은 경우: 놓은 위치에서 바로 3번(복귀) 실행.

### 4.4 잡기 → 결투 컷신 ★핵심
상세는 5장. 흐름만:
`이동 시작 → 두 말이 맞닿는 순간 정지 → 카메라 줌인 → 잉크 번짐 전환 → 결투 컷신(1.5~2.5초) → 잉크가 빠지며 보드 복귀 → 잡힌 말은 잉크로 녹아 사이드 '묘지'로`

### 4.5 특수 규칙 연출
| 상황 | 연출 |
|---|---|
| 체크 | 킹 칸에 붉은 잉크가 번지며 맥박처럼 깜빡, 페이지 가장자리가 붉게 물듦 |
| 캐슬링 | 킹과 룩이 동시에 이동, 룩이 킹 앞을 성벽처럼 지나감 |
| 앙파상 | 전용 미니 컷신 "옆구리 찌르기" |
| 프로모션 | 폰이 잉크로 녹았다 새 말로 다시 그려짐 (선택 UI: 4개의 말 스케치 중 클릭) |
| 체크메이트 | 전용 피날레: 공격한 말이 킹에게 다가가고, 킹이 왕관을 내려놓으며 잉크로 바램 → 일기장이 덮힘 → 결과 화면 |
| 스테일메이트/무승부 | 두 킹이 서로 고개 숙이고, 페이지가 조용히 바램 |

> 킹은 실제로 잡히지 않으므로 "킹이 죽는 컷신"은 체크메이트 피날레로 대체.

### 4.6 "보이지 않는 손" 자동 이동 (로봇 체스판 레퍼런스)
| 상황 | 연출 |
|---|---|
| AI의 수 | 목적 칸에 먼저 잉크 점이 찍히고(0.3초 예고) → 말이 들리지 않고 **바닥을 미끄러지듯** 이동, 지나간 자리에 옅은 잉크 선 |
| 되돌리기 (Undo) | 마지막 수가 **역재생**되듯 미끄러져 돌아가고, 잡혔던 말은 묘지에서 잉크가 다시 모여 그려지며 복귀 |
| 새 게임 | 흩어진 말들이 일제히 제자리로 미끄러져 정렬 (말마다 20ms 시차, 웨이브) |
| 다시 보기 (리플레이) | 기보를 따라 자동 재생, 컷신은 "짧게" 모드 |

## 5. 결투 컷신 시스템

### 5.1 조합 폭발 문제와 해결
말 6종 × 6종 = **36가지** 조합 (킹은 잡히지 않으니 실제로는 공격자 6 × 피해자 5 = 30). 30개 컷신을 각각 그리면 에셋이 감당이 안 됩니다. 그래서 **모듈 조합식**으로 설계합니다.

```
컷신 = [등장] + [공격자 공격 모션] + [임팩트 VFX] + [피해자 리액션] + [퇴장]
```

- **공격 모션** 6종 (공격자별 1개, 3장 표)
- **피해자 리액션** 4종 (공격 타입이 결정)
- **임팩트 VFX** 4종
- **특수 조합 오버라이드** 몇 개 (재미 포인트)

→ 실제 제작량: 공격 6 + 리액션 4 + VFX 4 + 특수 3~5 ≈ **20개 내외**로 30가지 조합을 모두 다르게 보이게 함.

### 5.2 공격 타입 → 리액션 매핑
| 공격 타입 | 공격자 | 피해자 리액션 | 임팩트 VFX |
|---|---|---|---|
| 찌르기 Pierce | 폰 | **꿰뚫림** → 뒤로 넘어지며 잉크로 녹음 | 잉크 방울 직선 분사 |
| 돌진 Charge | 나이트 | **날아감** → 화면 밖으로 튕겨 나감 | 잉크 충격파 링 |
| 마법 Ink Magic | 비숍 | **용해** → 그림이 선부터 지워지며 물에 녹음 | 소용돌이 잉크 |
| 분쇄 Crush | 룩 | **산산조각** → 종이 조각처럼 찢어져 흩날림 | 먹 폭발 + 화면 흔들림 |
| 베기 Slash/Cleave | 퀸, 킹 | **두 동강** → 사선으로 잘려 위아래가 미끄러짐 | 잉크 참격선 + 튀는 잉크 |

> "썰어버리는" 연출은 **피 대신 잉크**로 표현 → 잔혹도를 낮추면서 수채화 컨셉과 일치. 잘린 단면에서 잉크가 번져 나옴.

피해자 종류는 리액션의 **디테일**만 바꿉니다: 룩이 맞으면 돌 파편, 나이트는 말이 쓰러짐, 비숍은 지팡이가 날아감 등 (피해자 스프라이트의 '부서지는 파츠'로 처리).

### 5.3 특수 조합 (오버라이드)
| 조합 | 연출 |
|---|---|
| 폰 × 퀸 | 폰이 떨면서 눈을 감고 찌름 → 퀸이 놀란 표정으로 쓰러짐 ("다윗과 골리앗") |
| 폰 × 폰 | 두 병사가 창끼리 맞부딪혀 밀당 후 한 명이 넘어짐 |
| 나이트 × 나이트 | 마상 창 시합(마주 달려와 교차) |
| 퀸 × 퀸 | 쌍검 3합 교차 후 한쪽이 무너짐 |
| 앙파상 | 옆에서 몰래 찌르기 |

### 5.4 카메라 & 시간 구성 (기본 2.0초)
| 구간 | 시간 | 내용 |
|---|---|---|
| ① 접근 | 0~250ms | 공격자가 피해자 칸으로 이동, 맞닿는 순간 **히트스톱** |
| ② 줌인 & 전환 | 250~500ms | 두 칸 중심으로 카메라 2.5배 줌 → 수채 번짐 마스크로 컷신 페이지 전환 |
| ③ 대치 | 500~800ms | 양피지 배경 위 큰 일러스트 두 명이 좌우 배치, 서로 노려봄 |
| ④ 공격 | 800~1300ms | 공격 모션 + 임팩트 VFX + 슬로모션(0.3배 150ms) |
| ⑤ 리액션 | 1300~1800ms | 피해자 리액션 |
| ⑥ 복귀 | 1800~2000ms | 잉크가 빠지듯 전환 → 보드 원래 배율. 잡힌 말은 묘지로 |

- 아무 곳이나 클릭/스페이스 → **즉시 스킵**.
- 설정: 컷신 `항상 / 짧게(1초) / 끄기`. 끄기면 보드 위에서 간단한 잉크 터짐만.
- 같은 조합 반복 시 지루함 방지: 공격 모션에 좌우 반전·카메라 각도 2~3종 랜덤.
- `prefers-reduced-motion` 감지 시 기본값 "짧게", 화면 흔들림 OFF.

## 6. 일기장 해설 (riddle 오마주)

보드 옆(또는 아래) **일기장 여백**에 해설이 손글씨로 **한 획씩** 써지고, 다음 해설이 오면 이전 글씨는 바랩니다.

- 예: *"청색 기사가 e5의 병사를 쓰러뜨렸다."*, *"왕이 위험하다."*, *"…흥미로운 수로군."*
- 구현: SVG 텍스트 path에 `stroke-dasharray` 애니메이션 (riddle은 폰트를 골격화해 획을 추출했지만, 웹에선 SVG 경로 애니메이션으로 충분).
- 폰트: 한글 `Nanum Pen Script`(OFL), 영문 `Dancing Script`(OFL).
- 기보(PGN)도 일기장 뒷장에 손글씨로 기록.
- **확장 옵션(Phase 6)**: LLM 해설자 "일기장의 영혼" — 수를 둘 때마다 짧은 한 줄 코멘트. riddle처럼 OpenAI 호환 API 사용. 기본 버전은 규칙 기반 문장 템플릿.

## 9. 기술 스택 (권장)
| 영역 | 선택 | 이유 |
|---|---|---|
| 빌드 | Vite + TypeScript | Codex가 가장 안정적으로 다룸 |
| 렌더링 | **PixiJS v8** (WebGL) | 스프라이트·필터(변위/블러)·카메라 줌을 고성능으로 |
| 애니메이션 | **GSAP 3** (무료, 플러그인 포함) | 타임라인으로 컷신 시퀀스 구성에 최적 |
| 체스 규칙 | **chess.js** (BSD-2) | 합법 수, 체크, 캐슬링, 앙파상, 프로모션, PGN 전부 처리 |
| AI 상대 | **js-chess-engine** (MIT) 기본 / Stockfish WASM 선택 | Stockfish는 GPL-3 → 배포 시 소스 공개 의무 주의 |
| 사운드 | Howler.js | 간단, 모바일 대응 |
| 수채화 효과 | Pixi DisplacementFilter + 노이즈 텍스처, 커스텀 셰이더(종이 그레인) | 실시간 번짐/흔들림 |
| 테스트 | Vitest (규칙/상태), Playwright (스모크) | |

## 10. 개발 단계 (마일스톤)
| Phase | 목표 | 완료 기준 |
|---|---|---|
| 0 | 프로젝트 세팅 | `npm run dev`로 빈 화면 + 종이 배경 |
| 1 | 플레이 가능한 체스 (플레이스홀더 그래픽) | 2인이 끝까지 규칙대로 둘 수 있음, 하이라이트·불가 이동 되돌아오기 |
| 2 | 이동 모션 & 수채화 질감 | 말별 이동 모션, 잉크 번짐 필터, 착지 얼룩 |
| 3 | 결투 컷신 시스템 | 30개 조합 모두 컷신 재생(플레이스홀더 일러스트도 OK), 스킵·설정 |
| 4 | 일기장 해설·UI·사운드 | 한 획씩 써지는 해설, 묘지, 기보, 효과음 |
| 5 | AI 상대 & 실제 에셋 교체 | 3단계 난이도, 최종 아트 적용 |
| 6 | 폴리싱/확장 | 특수 조합 컷신, 모바일, LLM 해설(옵션) |

> **핵심 원칙: 에셋이 없어도 Phase 1~4가 돌아가게 플레이스홀더 먼저.** 아트는 병렬로 만들어 나중에 파일만 교체.
